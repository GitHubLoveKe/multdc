# 四级降级自治协议

> 版本：v1.0 | 日期：2026-09-21
> 状态：设计中

---

## 一、概述

多网区监控平台的核心设计目标之一是「中心不可用时，各区仍能自治运行」。本文档详细定义四级降级阶梯中每一级的触发条件、权威转移、可用能力、冻结能力，以及恢复时的行为。

设计原则：**宁可停采也不双主**（P5）。当无法达成共识时，选择留下「空洞」（slot 无人执行）而不是「双主」（两个节点同时执行同一 slot）。

---

## 三、降级阶梯总览

```
┌─────────────────────────────────────────────────────────────────────┐
│ L0 正常                                                              │
│ 权威：中心 + Coordinator + peer                                      │
│ 能力：全部                                                            │
│ 冻结：无                                                             │
├─────────────────────────────────────────────────────────────────────┤
│                         ↓ 中心不可达                                  │
├─────────────────────────────────────────────────────────────────────┤
│ L1 中心不可达                                                         │
│ 权威：区内 Coordinator                                                │
│ 能力：采集/检测/接管/驱离/再均衡                                        │
│ 冻结：任务定义变更                                                     │
├─────────────────────────────────────────────────────────────────────┤
│                         ↓ Coordinator 主不可用                        │
├─────────────────────────────────────────────────────────────────────┤
│ L2 Coordinator 主不可用                                                │
│ 权威：备 Coordinator                                                  │
│ 能力：同 L1                                                           │
│ 冻结：同 L1 + 切换期暂停迁移                                           │
├─────────────────────────────────────────────────────────────────────┤
│                         ↓ 主备皆失                                    │
├─────────────────────────────────────────────────────────────────────┤
│ L3 协调器全失                                                          │
│ 权威：Job Scheduler 集群（纯分布式）                                     │

│ 冻结：再均衡/配置变更/新节点加入                                          │
└─────────────────────────────────────────────────────────────────────┘
```

## 四、各级详细定义

### 4.1 L0 — 正常运行

**触发条件**：所有组件正常运行。

**权威分布**：
| 决策类型 | 权威 | 说明 |
|---------|------|------|
| 任务定义（TaskSpec/RuleSpec） | 中心控制面 | 唯一全局权威 |
| 归属决策（slot ownership） | Coordinator + peer 协商 | 区内实时权威 |
| 采集执行 | Job Scheduler → Agent | 执行层 |
| 观测与审计 | 中心控制面 | 只观测，不干预 |

**可用能力**：
- ✅ 采集任务定义与下发
- ✅ RC 规则定义与下发
- ✅ slot 归属协商与变更
- ✅ 节点接管与驱离
- ✅ 再均衡（slot 迁移）
- ✅ 新节点加入
- ✅ 配置变更（存储模式、抓取间隔等）
- ✅ 全局观测矩阵
- ✅ 告警汇聚与通知

**冻结能力**：无。

**数据流**：
```
中心 ──Manifest──→ Zone Agent ──广播──→ Job Schedulers
                                              │
                                    slot 归属协商（Coordinator 仲裁）
                                              │
                                    Agent 采集 → OTel → Storage
```

---

### 4.2 L1 — 中心不可达

**触发条件**：Zone Agent 连续 N 次（默认 3 次）无法连接中心控制面。

**权威转移**：
| 决策类型 | L0 权威 | L1 权威 | 变化 |
|---------|---------|---------|------|
| 任务定义 | 中心 | **冻结** | 无法获取新定义 |
| 归属决策 | Coordinator + peer | Coordinator + peer | **不变** |
| 采集执行 | Job Scheduler | Job Scheduler | **不变** |
| 观测与审计 | 中心 | **区内自记** | 降级为本地日志 |

**可用能力**：
- ✅ 采集任务执行（按最后 Manifest）
- ✅ RC 规则评估（按最后 RuleSpec）
- ✅ 节点接管（节点故障时其他节点接管 slot）
- ✅ 驱离（主动下线节点）
- ✅ 再均衡（slot 迁移）
- ✅ 区内告警产生（RC 正常工作）
- ❌ 告警汇聚到中心（跨区通道中断）
- ❌ 任务定义变更（无法获取新 Manifest）
- ❌ 新节点加入（需要 Coordinator 签发 epoch，但 Coordinator 仍在）

**冻结能力**：任务定义变更（TaskSpec/RuleSpec 更新）。

**关键行为**：
- Zone Agent 缓存最后已知 Manifest，标记 `sync_status: stale`
- 区内按最后 Manifest 继续运行
- RC 继续评估规则，告警写入本地队列（等待中心恢复后补发）
- Coordinator 继续签发 epoch、处理归属协商

**持续时间**：无限期（设计上支持长期 L1 运行）。

---

### 4.3 L2 — Coordinator 主不可用

**触发条件**：备 Coordinator 检测到主 Coordinator 心跳丢失（连续 M 次，默认 5 次）。

**权威转移**：
| 决策类型 | L1 权威 | L2 权威 | 变化 |
|---------|---------|---------|------|
| 归属决策 | 主 Coordinator | **备 Coordinator** | 切换 |
| epoch 签发 | 主 Coordinator | **备 Coordinator** | 切换 |

**可用能力**：
- ✅ 同 L1 所有能力
- ⚠️ 迁移暂停（切换期间冻结 slot 迁移，防止归属冲突）
- ❌ 主 Coordinator 独有的功能（如果有）

**冻结能力**：L1 冻结 + 切换期间暂停 slot 迁移。

**切换过程**：
```
时间线：
  t0: 主 Coordinator 最后一次心跳
  t0 + 15s × 5: 备检测到主不可用
  t0 + 15s × 5 + ε: 备发起接管
    ├── 检查 RDS 租约（档位 B）或 etcd 选举（档位 A）
    ├── 确认自己获得权威
    ├── 广播新的 Coordinator 身份
    └── 恢复 slot 迁移能力
  t0 + 15s × 5 + 2ε: 区内恢复正常操作
```

**切换时间预算**：
- 检测时间：15s × 5 = 75s（可配置）
- 接管时间：< 5s
- 总切换时间：~80s
- 切换期间影响：slot 迁移暂停，采集不受影响

**关键约束**：
- 切换期间不允许 slot 迁移（防止新旧 Coordinator 同时签发 epoch）
- 如果主 Coordinator 在切换完成前恢复，必须退让（备已接管）
- 采用 fencing 机制防止「僵尸主」重新获得权威

---

### 4.4 L3 — 协调器全失

**触发条件**：所有 Coordinator 节点（主 + 备）均不可用。

**权威转移**：
| 决策类型 | L2 权威 | L3 权威 | 变化 |
|---------|---------|---------|------|
| 归属决策 | 备 Coordinator | **Job Scheduler 多数派** | 退化为纯分布式 |
| epoch 签发 | Coordinator | **无法签发新 epoch** | 冻结 |

**可用能力**：
- ✅ 采集任务执行
- ✅ RC 规则评估
- ✅ 节点检测（VRRP peer 互探继续）
- ✅ 多数派接管（节点故障时，多数节点同意后可接管其 slot）
- ❌ 再均衡（需要 Coordinator 协调全局视图）
- ❌ 配置变更
- ❌ 新节点加入（无法签发 epoch）
- ❌ 驱离编排（需要 Coordinator 编排）

**冻结能力**：再均衡、配置变更、新节点加入、驱离编排。

**退化行为**：
```
正常归属协商（需要 Coordinator）：
  Node A 故障 → Coordinator 确认 → 签发新 epoch → 其他节点接管

L3 归属协商（纯多数派）：
  Node A 故障 → 其余节点 peer 检测 A 过期
  → 多数派投票（>50% 存活节点同意）
  → 接管 A 的 slot（使用 A 的最后 epoch_token + 1）
  → 如果无法达成多数派 → slot 留空（不双主）
```

**关键约束**：
- 无法签发新 epoch → 无法支持新节点加入
- 多数派接管需要 >50% 存活节点同意
- 无法达成多数派时，slot 留空（宁可停采也不双主）
- 2 节点区在 L3 时：1 节点故障 = 无法达成多数派 → 全区停摆

**恢复路径**：
- Coordinator 恢复后，自动重新获得权威
- 需要扫描当前 slot 归属状态，与「期望态」对比
- 触发「协商式再均衡」（非强制覆盖）

## 五、降级转换矩阵

| 当前级别 | 触发事件 | 目标级别 | 转换行为 |
|---------|---------|---------|---------|
| L0 | 中心不可达 | L1 | Zone Agent 标记 stale；区内继续运行 |
| L0 | Coordinator 主不可用 | — | 先转 L1（如果中心仍可达则不降级）→ 再转 L2 |
| L1 | Coordinator 主不可用 | L2 | 备接管；暂停迁移 |
| L1 | Coordinator 全失 | L3 | 退化为纯多数派；冻结再均衡 |
| L2 | 备也不可用 | L3 | 退化为纯多数派 |
| L3 | Coordinator 恢复 | L1 或 L2 | 恢复 Coordinator 权威；协商式再均衡 |
| L2 | 主恢复 | L1 | 主恢复观测角色；备继续担任决策（避免反复切换） |
| L1 | 中心恢复 | L0 | Zone Agent 重新同步 Manifest；恢复正常 |

**防抖动规则**：
- 降级触发需要连续 N 次检测失败（避免瞬时网络抖动触发降级）
- 升级（恢复）需要连续 M 次检测成功（避免反复跳变）
- Coordinator 主恢复后不自动夺回决策权（避免再次切换震荡）

## 六、恢复协议

### 6.1 核心原则：承认既成事实

> 恢复时承认降级期间的归属决定，但如果与期望态矛盾，触发「协商式再均衡」而非强制覆盖。

### 6.2 恢复流程

```
中心/Coordinator 恢复
    │
    │ 1. 获取当前区内状态快照
    │    (从 Job Scheduler 收集当前 slot 归属)
    │
    │ 2. 对比期望态（最后 Manifest 中的归属建议）
    │    ├── 一致 → 无需操作，直接恢复 L0
    │    └── 不一致 → 进入协商式再均衡
    │
    │ 3. 协商式再均衡
    │    ├── 中心生成「建议再均衡方案」
    │    ├── 通过 Zone Agent 下发到区
    │    ├── Coordinator 评估方案可行性
    │    │   ├── 可行 → 执行再均衡
    │    │   └── 不可行 → 反馈原因，中心调整
    │    └── 再均衡完成 → 恢复 L0
    │
    │ 4. 补发降级期间积压的告警
    │    (从区内告警队列读取)
```

### 6.3 「既成事实」的边界

| 降级期间的决定 | 恢复时是否承认 | 说明 |
|--------------|---------------|------|
| slot 归属变更 | ✅ 承认 | 即使与期望态不同 |
| 节点驱离 | ✅ 承认 | 被驱离的节点不会自动恢复 |
| 配置变更 | ❌ 不承认 | L1-L3 冻结了配置变更 |
| 新节点加入 | N/A | L1-L3 冻结了新节点加入 |
| RC 规则变更 | ❌ 不承认 | L1-L3 冻结了规则变更 |

## 七、告警降级处理

### 7.1 降级期间的告警行为

| 级别 | RC 状态 | 告警产生 | 告警汇聚 | 告警通知 |
|------|---------|---------|---------|---------|
| L0 | 正常 | ✅ | ✅ → 中心 | ✅ |
| L1 | 正常 | ✅ | ⚠️ 本地队列缓存 | ❌ 延迟（等中心恢复） |
| L2 | 正常 | ✅ | ⚠️ 同 L1 | ❌ 同 L1 |
| L3 | 正常（如果有本地存储） | ✅ | ⚠️ 同 L1 | ❌ 同 L1 |

### 7.2 告警补发

- 降级期间告警写入区内本地队列（文件/SQLite）
- 中心恢复后，Zone Agent 批量上传告警队列
- 中心告警管理模块处理去重（降级期间可能产生重复告警）
- 补发告警标记 `degraded_mode: true`，便于区分

### 7.3 Mode A 告警特殊处理

Mode A 网区无本地 RC，告警能力受限：

| 级别 | Mode A 告警能力 |
|------|----------------|
| L0 | 中心部署「虚拟 RC」评估 mode A 规则（如果启用） |
| L1 | 无告警能力（中心不可达 + 无本地 RC） |
| L2-L3 | 同 L1 |

**[建议]**：Mode A 定位为边缘/低优先级网区，接受 L1 期间的告警盲区。关键网区应使用 mode B/C。

## 八、设计决策与替代方案

### DEC-DEG-01：降级检测的超时阈值

| 方案 | 检测超时 | 优点 | 缺点 |
|------|---------|------|------|
| A：激进 | 15s × 2 = 30s | 快速检测，快速降级 | 误报率高（网络抖动） |
| B：保守 | 15s × 5 = 75s | 误报率低 | 降级感知慢 |
| C：自适应 | 根据网络质量动态调整 | 最优平衡 | 实现复杂 |

**[建议]**：阶段 1 用方案 B（保守），阶段 3 评估方案 C。

### DEC-DEG-02：恢复时的归属处理策略

| 方案 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| A：承认既成事实 | 降级期间的归属决定全部保留 | 稳定；不中断正在执行的采集 | 可能偏离期望态 |
| B：强制恢复 | 恢复后强制回到期望态 | 与期望态一致 | 中断采集；可能引发震荡 |
| C：协商式再均衡 | 承认现状，但触发渐进式再均衡 | 平衡 | 实现较复杂 |

**[建议]**：方案 C。既尊重降级期间的自治决定，又逐步回归全局最优。

### DEC-DEG-03：L3 模式下 2 节点区的处理

| 方案 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| A：接受停摆 | 2 节点区 L3 时无法达成多数派，全区停摆 | 安全（不双主） | 可用性低 |
| B：单节点自治 | 2 节点区 L3 时，存活节点独立接管 | 可用性高 | 违反多数派原则 |
| C：Witness 节点 | 部署轻量 witness 避免 L3 | 根本解决 | 额外资源 |

**[建议]**：方案 A + 推荐方案 C。2 节点区应部署 witness 节点避免 L3 场景。
