# 凭据服务 (Credential Service)

> **版本：v2.0** | **日期：2026-09-22** | **状态：已废弃**

---

## 一、变更说明（v1.0 → v2.0）

原 v1.0 设计了独立的凭据服务模块，包含加密存储、RBAC 访问控制、凭据轮换、三阶段安全模型演进等复杂机制。

**v2.0 变更：** 凭据已合并入实例记录（DEC-016），独立凭据服务不再必要。

### 废弃原因

1. **四层属性模型简化**：实例属性统一为 identity / connection / config / credential 四层，凭据作为实例的第四层属性直接存储在实例记录中
2. **消除额外依赖**：Agent 采集不再需要额外调用凭据服务 API，减少网络开销和故障点
3. **简化 Manifest**：Manifest 中直接包含完整实例信息（含凭据），通过传输层加密保障安全

### 功能迁移映射

| 原 v1.0 功能 | v2.0 归属 | 说明 |
|-------------|----------|------|
| 凭据加密存储 | 实例管理模块 | 凭据字段存储在 instance 记录中 |
| 凭据引用（credential_id） | 已废弃 | 不再需要引用，凭据直接内嵌 |
| 凭据分发 API | 已废弃 | Agent 从 Manifest 直接获取 |
| RBAC 访问控制 | 实例管理模块 | 实例级别的权限控制 |
| 凭据轮换 | 实例管理模块 | 通过更新实例记录实现 |
| 审计日志 | 实例管理模块 | 实例变更审计覆盖凭据变更 |

## 二、当前凭据管理方式

### 2.1 四层属性模型

凭据作为实例的第四层属性，与实例记录一体管理：

| 层级 | 内容 | 示例 |
|------|------|------|
| identity | 身份标识 | instance_id, name, type |
| connection | 连接信息 | host, port, protocol |
| config | 采集配置 | scrape_interval, metrics_path |
| credential | 认证凭据 | username, password, ssh_key, token |

### 2.2 安全保障

凭据虽内嵌于实例记录，仍通过以下措施保障安全：

- **传输加密**：控制面 → 协调层 → Agent 全链路 TLS
- **存储加密**：数据库中凭据字段使用 AES-256-GCM 加密
- **访问控制**：基于实例级别的 RBAC，控制谁能查看/修改实例凭据
- **审计追踪**：实例记录变更（含凭据字段）记录审计日志

### 2.3 凭据轮换

凭据轮换通过更新实例记录中的凭据字段实现：

1. 管理员在控制面更新实例的凭据字段
2. 控制面下发更新的实例记录至协调层
3. Agent 通过 SyncTasks 获取更新的实例信息
4. 下次采集使用新凭据

## 三、已废弃机制

| 已废弃数据模型 | 替代 |
|--------------|------|
| credential 表 | instance 表的 credential 层字段 |
| credential_access_policy 表 | 实例级权限控制 |
| credential_audit_log 表 | 实例变更审计日志 |
| encryption_key 表 | 实例字段级加密（复用相同机制） |
| 凭据分发 API（/fetch, /fetch-batch） | Manifest 直接包含 |
| 三阶段安全模型演进 | 不再需要，凭据已在实例记录中 |

## 四、设计决策

**DEC-016：凭据合并入实例记录**

- **决策**：取消独立凭据服务（C7），凭据作为实例记录的第四层属性（credential 层）直接管理
- **原因**：
  - 消除 Agent 对凭据服务的额外 API 调用
  - 简化架构，减少关键依赖
  - 四层属性模型已足够清晰，无需独立的凭据存储
- **前提**：传输层全链路 TLS 加密，数据库凭据字段加密存储
- **影响**：凭据轮换通过更新实例记录实现，无需独立的凭据轮换流程
