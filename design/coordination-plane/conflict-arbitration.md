# 冲突仲裁

> **版本：v2.0** | **日期：2026-09-22** | **状态：大幅简化**

---

## 一、变更说明（v1.0 → v2.0）

原 v1.0 设计了独立的冲突仲裁模块，包含 Epoch Fencing、多数派投票、2 节点 Witness 方案、偶数节点平局打破等复杂机制。

**v2.0 变更：** Rendezvous Hashing + Gossip 协议使绝大多数冲突场景自动消解，独立仲裁模块不再必要。

### 已废弃机制

| 原 v1.0 机制 | v2.0 状态 | 替代方案 |
|-------------|----------|---------|
| Epoch Fencing | 已废弃 | Rendezvous Hashing 确定性分配，无所有权冲突 |
| 多数派投票裁决 | 已废弃 | Gossip 最终一致性收敛 |
| 2 节点 Witness 方案 | 已废弃 | Gossip 直接处理 2 节点场景 |
| 偶数节点平局打破 | 已废弃 | 哈希分配无投票环节 |
| Manifest 版本冲突 | 已废弃 | 双层版本校验（content_hash + root_hash）自动发现并同步 |
| "宁缺勿滥"原则 | 已替换 | "重复优于空洞"（DEC-019） |

## 二、当前冲突解决机制

### 2.1 核心原理

冲突解决依赖两个基础机制的组合：

1. **Rendezvous Hashing**（最高随机权重）：每个 target 的 owner 由 `hash(target_id, node_id)` 确定性计算。所有节点独立计算，结果一致。无"所有权声明"环节，故无所有权冲突。

2. **Gossip 协议**：节点拓扑变更（新增/故障/恢复）通过 Gossip 传播。当所有节点对成员列表达成共识后，各自独立执行相同的哈希计算，自然收敛到相同的分配方案。

```
冲突消解流程:

  节点 A 认为 target X → 自己
  节点 B 认为 target X → 自己
  （说明 A 和 B 的成员列表不一致）

  → Gossip 交换成员列表
  → 收敛到一致的成员列表
  → 各节点独立计算 hash(target_X, member_list)
  → 结果一致，冲突自动消解
```

### 2.2 网络分区场景

v1.0 原则："宁缺勿滥"（留空优于重复）
v2.0 原则：**"重复优于空洞"**（DEC-019）

网络分区期间：
- 各分区独立运行，各自计算哈希分配
- 同一 target 可能被多个分区同时采集 → **允许重复采集**
- 重复采集的数据在下游（控制面/存储层）通过 fingerprint 去重
- 分区恢复后，Gossip 自动收敛，分配方案统一

```
为什么"重复优于空洞":

  重复采集:
    - 下游去重可处理
    - 数据完整性有保障
    - 告警不会遗漏

  空洞（不采集）:
    - 数据缺失不可恢复
    - 可能导致告警遗漏
    - 监控盲区比数据重复更危险
```

### 2.3 数据一致性

| 场景 | v1.0 处理 | v2.0 处理 |
|------|----------|----------|
| 节点故障 | 多数派确认后接管 | Gossip 标记 dead → 哈希重算 → 其他节点自动吸收 |
| 节点恢复 | 需重新注册 | Gossip 标记 alive → 哈希重算 → 自动归位 |
| 网络分区 | 少数派冻结 | 各分区独立运行，允许重复，恢复后自动收敛 |
| 版本不一致 | 强制同步 Manifest | content_hash 对比 → 差异实例级别同步 |

## 三、残留的可观测需求

虽然独立仲裁模块已取消，以下可观测能力仍有价值：

- **重复采集检测**：监控 fingerprint 去重率，异常升高可能指示拓扑不收敛
- **拓扑分歧监控**：检测各节点成员列表的差异程度，差异持续过大说明 Gossip 异常
- **分区历史日志**：记录检测到的网络分区事件，供事后分析

这些可观测需求由 Scheduler 通过 Proxy 上报控制面实现，不需要独立模块。

## 四、设计决策

**DEC-018：Rendezvous Hashing 替代 Slot 模型**

- **决策**：取消 Slot 分配模型，改用 Rendezvous Hashing（最高随机权重）
- **原因**：确定性哈希分配天然无所有权冲突，消除 Epoch Fencing、多数派投票等全部复杂机制
- **影响**：冲突仲裁模块大幅简化为 Gossip 收敛 + 哈希重算

**DEC-019：重复优于空洞**

- **决策**：网络分区等不确定场景下，允许重复采集而非留空
- **原因**：数据缺失不可恢复，数据重复可通过下游去重处理。监控盲区的代价大于重复数据的代价
- **前提**：下游存储层需支持 fingerprint 去重
